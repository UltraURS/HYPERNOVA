# HYPERNOVA 0.1.1-dev

日期：2026-11-16。versionCode `2`，沿用包名与调试签名，可覆盖安装 0.1.0-dev。当前仍是未经真机验收的开发版。

## 恢复出厂入口遗漏修复

原实现只隐藏普通 Preference 的 `factory_reset_key`。“更多设置 → 在查找其他设置吗？”使用的是独立推荐系统，因此原过滤没有覆盖。

在用户 Settings 样本的 `assets/recommend.json` 中找到：sourcePageIndex `4`，targetPageIndex `1008`，跳转为 `com.android.settings/.SubSettings`，`:settings:show_fragment` 为 `com.android.settings.MiuiMasterClear`。

本版在同一个“隐藏恢复出厂入口”开关下处理：

- 保留“我的设备”中的普通条目隐藏。
- 在 `RecommendUIHelper.getLinkData(RecommendItem)` 调用前读取配置 Intent，调用后读取最终链接 Intent；对上述精确组件/fragment 返回空链接。
- 原 `addRecommendItem` 对空链接返回 false，不添加该推荐。其他推荐保留，不按中文标题过滤，也不删除整个推荐分类。

双重检查是因为推荐代码可能优先采用搜索索引中的 Intent，或用 `getRawIntent()` 替换解析结果。配置目标可以稳定识别样本中的已知重置推荐，最终目标检查覆盖动态生成的同一跳转。

原始 DEX 声明位于 Settings 的 `classes2.dex`。相关声明已加入 `tools/verify-targets.py`；本地反编译在 `.local/analysis/settings/RecommendUIHelper-expanded.java`。复杂的索引分支存在反编译重建提示，本版不修改它们，只使用明确的配置、链接返回契约和精确跳转匹配。真机是否命中仍须日志证明。

## OTA 的实际处理范围

用户已再次确认：**仅 OTA 客户端范围；客户端缺失时显示不适用。** 本版没有添加设备级 DNS、hosts、防火墙或全局网络 Hook。

模块界面新增实际检测，通过 Manifest 的精确包可见性声明查询当前用户下的 `com.android.updater`：

| 检测结果 | 显示与行为 |
| --- | --- |
| 找不到目标客户端 | 不适用，不启用服务器阻断 |
| 检测到客户端 | 待适配，尚未核验请求链，不声称已阻断 |
| 查询受限 | 无法确认，不把查询失败当作客户端不存在 |

进入设置页或返回前台时更新检测结果，不再写死“当前 ROM 无更新器”。检测只针对这个明确包名，不证明其他客户端不存在。

现有材料没有更新器 APK，也没有已核验的 OTA 端点与请求实现，因此**本次没有实现可对存在的 OTA 客户端生效的网络阻断**。Settings 中出现的 `unlock.update.*` 等字符串不能据名字当作 OTA 服务器封锁。未来客户端出现时，需要其同机 APK/包信息，再定位检查、下载、安装委托与网络发送点。

## 本期范围调整

恢复出厂设置按最新要求只隐藏入口，取消之前的执行链拦截计划。模块界面不再把“阻止重置”列为待完成保护功能，也不要求勾选系统框架。设置搜索和其他直达入口尚未全面覆盖。

## 升级与验收

1. 覆盖安装新 APK，保留 LSPosed 的系统界面与设置作用域。
2. 保持“隐藏恢复出厂入口”开启，重启手机。
3. 日志出现 `settings-entry INSTALLED` 后，进入“更多设置”检查底部推荐；如果页面早于后台校验创建，离开后重新进入。
4. 查找 `[HYPERNOVA] reset-recommendation OBSERVED`，同时确认其他推荐仍可见、可点击。
5. 关闭此开关并重启后，确认入口恢复；无需点击最终恢复出厂确认。
6. 查看 OTA 状态卡，当前无更新器时应显示“不适用”，不显示阻断成功。

本地验证结果：12 项单元测试通过，17 个原始 DEX 成员及样本哈希匹配，Lint 无问题，APK 构建、签名及 ZIP 对齐检查通过。签名证书与 0.1.0-dev 一致。未执行手机安装、真实 OTA 请求或擦除操作。
