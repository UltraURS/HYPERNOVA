# 通知中心一键清理

更新：2026-11-17，0.2.7-dev。功能始于 0.2.4-dev，适用已固定 SHA-256 的 SystemUI 样本。未进行开发端真机测试。

## 控件与范围

新增开关位于“设置 → 系统界面 → 通知中心一键清理”，默认关闭。复用 SystemUI 的 `NotificationDismissViewController.dismissView`，保留原生点击、清理动画和触感；不添加全屏悬浮窗，也不重复创建清理按钮。

`updateOrientation()` 后将控件放在底部水平居中，底边距为导航栏／屏幕缺口安全距离加上容器高度的 2.5%（最低 24 dp）。0.2.7 依据用户提供的后台清理按钮位置下移，较原来的 7.5%／64 dp 约降低屏幕高度的 5%；具体差值取决于容器高度和密度。监听父容器布局变化，旋转或窗口尺寸改变时重新定位。控件的辅助说明为“一键清理，保留锁定通知”。

原生 `getShowDismissView()` 通过 `hasNotifications(0, true)` 判断是否有可清除通知；这里的 false 参数表示“不可清除通知”，并不表示“全部通知”。模块仅在该显示判断期间，将两种通知的存在性取 OR，允许只剩常驻通知时仍显示按钮。锁屏、悬浮通知、QS 详情、控制中心切换、亮度镜像等原生显示限制继续生效；没有通知时隐藏。

`onInit()` 及后续 `getShowDismissView()` 均可接入已有控件，避免后台 APK 校验期间控件已初始化导致遗漏。每个控件只注册一次布局监听。

## 锁定保护

原生 `clearNotifications(0, ...)` 在动画结束后调用 `NotifCollection.dismissAllNotifications(userId)`，后者直接向系统服务发送 `onClearAllNotifications`。因此仅修改行的可滑动状态、动画列表或 `includeChildInClearAll()` 无法保护锁定通知。

启用“通知锁定与置顶”时，保护链与清理按钮开关独立：

1. `includeChildInClearAll()` 排除锁定行及含锁定子通知的分组行，避免提前播放移除动画。
2. 有有效锁定目标时，在 `dismissAllNotifications()` 向系统服务发出批量请求前截断该调用。按原生当前用户、`isClearable()`、bubble 标志及已清除状态筛选快照，再通过 `dismissNotifications()` 发出逐条请求，继续使用原生可见性统计和清理拦截器。
3. `dismissNotifications()` 同时过滤锁定项，覆盖原生折叠通知等按列表清理路径。锁定子通知所在的分组摘要也保留，避免清摘要时由系统连带删除子通知；其他未锁定子通知可清理。
4. 如果锁定的是分组摘要，则保留其子通知，避免最后一条子通知被清除后系统自动删除摘要。这是摘要本身被选中时的分组保留行为；锁定单条子通知不锁定其他同类通知。

未锁定的置顶通知按普通通知清理；同一条同时锁定／置顶时保留。系统不可清除的常驻通知不强制删除。应用自行撤回或系统真正移除通知后，原有 `tryRemoveNotification()` 清除该 key 的选择状态，不重新发通知。

没有锁定目标或目标已消失时沿用原生清理。有锁定目标但保护链发生错误时停止本次清理并提示，不回退到无保护的批量接口。通知内容、应用名称与 key 不写日志；只记录接入状态和逐条清理数量。

## 本地验证与设备验收

新增 4 项纯逻辑测试覆盖：锁定与仅置顶的区别、锁定子通知与分组摘要、锁定摘要的子通知保留、取消锁定及无关分组。加上既有测试共 40 项。新增成员纳入固定固件声明检查，共 116 项；静态签名命中不表示真机行为已经通过。

设备需验证 T30：混合普通／锁定／仅置顶／常驻通知、同组多个子通知、锁定摘要、折叠通知、取消锁定后再次清理、只剩锁定通知及空列表；并检查展开／收起／控制中心／锁屏、旋转、系统深浅色和 HyperCeiler 共存。
