# 实施与验收计划

执行顺序为 `P0 → P1 → P2 → P3 → P4 → P5 → P6`，通知和侧边栏增量分别记为 P2b、P2c。当前 0.2.4-dev：已有 P1 工程/配置、P2 流量、P2b 通知、P2c 双侧侧边栏手势与部分设置入口代码，并增加一键清理及页面动画。真机退出条件尚未通过，P3 完整提示/搜索和存在客户端时的 P4 尚未完成；P5 已按新需求改为入口隐藏，不再包含执行链。当前 ROM 无更新器，P4 经证据确认后可记为不适用并继续 P5。每阶段先建立可验证条件，再做最小实现。

- [x] 记录 6 个二进制样本 SHA-256、APK 版本、Manifest 声明与初始截图。

产出：固件清单、原始 DEX 核验表、调用链记录和初始验收截图。退出条件：至少明确一个流量磁贴目标及其生命周期；OTA 和重置的待补充路径有清晰记录。目标材料不足不阻止 P1 的空模块工作，但阻止对应功能 Hook 的实现与支持声明。

采集以读取为主；不为了查路径执行 OTA 安装、恢复出厂、删除包或清空设置数据。现有原件保留在 `apks/`，补充信息可放 `.local/firmware/<profile>/`；两者从版本控制排除，只提交哈希、签名和分析结论。

退出条件：APK 构建/Lint 通过；目标设备能读取相同配置；所有开关关闭时原系统行为不变；停用模块并重启后探测 Hook 不再加载。

## P4：OTA 检查、下载和安装请求

**目标：新的 OTA 请求无法越过已确认的客户端执行边界。**

当前 ROM 的分支：先取得包缺失证据，核查 Settings 是否委托给其他 OTA 组件；确认没有目标客户端时，相关路径记 `NOT_APPLICABLE`，继续 P5。不得把未安装客户端记为请求阻断通过，不下载其他 ROM 的更新器补齐实验。若日后出现客户端，重新进行本阶段。

- [ ] 对手动检查、启动任务、定时任务和各子进程建立调用链。
- [ ] 明确客户端到 HTTP、下载服务、`update_engine` 或其他安装服务的委托点。
- [ ] 在委托前拒绝检查/下载/安装，包括已缓存本地更新包的客户端安装入口。
- [ ] 补充已识别 OTA 网络路径拦截，验证错误和取消回调正常结束，没有无限重试或持续唤醒。
- [ ] 对观察窗口内的请求、委托次数和任务唤醒做证据记录；仅看“无新版本”页面不算验证。
- [ ] 查询并记录已有更新状态；若启用模块前已有更新交给底层引擎，不把它算作模块已经阻止，也不自动中断或修改引擎。

退出条件：T09–T12 通过；新增检查/下载/安装不会交给网络或底层服务；对未观察到的原生/独立进程路径明确标注。网络抓包或日志中“没有流量”须同时证明测试入口被触发及 Hook 命中，避免把网络本来不可达误判为有效。

## P6：联合验收与交付

**目标：三组功能组合工作、可恢复，并准确说明适配范围。**

- [ ] 三组功能分别启用、全部启用、全部关闭，验证配置版本与进程日志一致。
- [ ] 覆盖冷启动、未解锁、重启 SystemUI、插件重载、重新进入 Settings 和设备重启；Updater 仅在存在且已适配时验证。
- [ ] 记录 HyperCeiler 版本、作用域和配置快照，验证共存时流量标题、刷新及设置过滤；冲突时仅对已定位的重叠项作对照。
- [ ] 使用错误固件/缺少方法的测试样本验证只跳过对应功能，不崩溃、不误报已保护。
- [ ] 完成停用恢复验证，记录实际框架分支对应的恢复办法。
- [ ] 输出 APK、SHA-256、构建工具/依赖版本、适配档案、已知限制和验收记录。
- [ ] 复核移植文件来源与许可声明，不打包厂商 APK/JAR、原项目私有素材或无关功能。

退出条件：必须通过的项目有证据；缺失覆盖明确标注，不以测试 APK 冒充全功能稳定版。若某组未完成，可交付标明未支持的开发版本，但不能把首期总体目标标为完成。

## 每次修改的开发流程

1. 在适配档案写明目标方法、所属进程、完整签名、选择原因和待验证行为。
2. 修复问题时先添加能复现问题的测试；新策略用正向与反向用例约束范围。纯文档、文案等低影响变更不机械添加测试。
3. 只修改相关功能及其测试；不顺带重构源项目或迁移其他功能。
4. 运行相关单元测试；Hook 目标变更运行 DEX 核验；可打包变更运行 Lint 与 APK 构建。
5. 真机按改动对应行验证；影响进程加载、配置或系统框架时补充启动与停用恢复检查。
6. 更新档案中的证据、已知限制、构建号和状态后交付。

构建入口为 `gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`，也可使用 `build.ps1`。`tools/verify-targets.py --apks <目录>` 核验当前基础 Hook 的哈希和成员；不使用 Connect Colours 的 Android 13 样本作为目标证据。
